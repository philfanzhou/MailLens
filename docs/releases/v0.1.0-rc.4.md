## Purpose and changes

This RC packages the merged [#42](https://github.com/philfanzhou/MailLens/issues/42)
caller and context changes since published rc.3. It supplies a fixed candidate for
native Windows/Classic Outlook validation in [#9](https://github.com/philfanzhou/MailLens/issues/9).
Live validation and human model assessment remain **pending**. Stable `v0.1.0`
still requires #9 and separate stable version/SHA/publication direction under
[#11](https://github.com/philfanzhou/MailLens/issues/11).

- [PR #46](https://github.com/philfanzhou/MailLens/pull/46): a schema-2 `get`
  request omitting `bodyLength` now requests 2000 Unicode scalars instead of
  20000. Explicit lengths, scalar offsets, response/status/exit behavior and
  exact identity/consistency checks remain compatible.
- [PR #47](https://github.com/philfanzhou/MailLens/pull/47): the shipped
  `-View -RequestPath` caller emits compact UTF-8 output and an external run
  path; `-View -RunDirectory -Label` selects follow-up get bodies through an
  immutable private format 1 index. Exact mailbox/item identities stay in
  private files. Raw `-RequestPath/-OutputPath` mode remains available. The
  authoritative association, failure and concurrency rules remain in
  [the #1 contract](https://github.com/philfanzhou/MailLens/issues/1#single-authoritative-first-release-technical-contract).
- [PR #49](https://github.com/philfanzhou/MailLens/pull/49): ordinary browse,
  keyword/list-only search and first label get use a self-contained Chinese
  entry; advanced/error/multi-chunk references load only when needed. Default
  answer guidance is at most three necessary first chunks of 2000 scalars each,
  6000 total, fewer when enough. Mandatory load is 5396 Unicode characters
  versus the approved original 23297 (76.84% reduction). Characters divided by
  two is only a rough token estimate, not a tokenizer measurement, latency
  result, model-obedience result or overflow-prevention guarantee.

Distribution: complete Git source snapshot and GitHub automatic source archives.
No standalone binary, extra release asset, package registry or marketplace.

## Compatibility and installation

Target: OpenCode on native Windows, Classic Outlook and Windows PowerShell 5.1.
The pinned native discovery baseline remains OpenCode 2.0.28, introduced in rc.3;
supporting it does not certify all past/future versions. No New Outlook,
Graph/OAuth, additional runtime or other-agent adapter is added. Native CI
versions/results: **[complete externally from the exact-main run]**.

Query schema remains **2**, ownership receipt schema **1**, and the new private
selection index format is **1**. Existing raw callers, response/status/exit
behavior and explicit body lengths remain compatible; the omitted get default
intentionally changes from 20000 to 2000 scalars. New managed modes and indexes
require the complete new package; older packages cannot consume them.

No mailbox/configuration/query/receipt migration is required. Update the complete
owned package from the verified fixed source, restart OpenCode, and use fresh
requests/results and owned private run state. Verify the exact selected installed
path/content/resources. Upgrading the CLI alone does not update MailLens. Do not
mix individual scripts or instructions. Deliberate whole-package rollback to rc.3
restores its older default/instructions and lacks the managed modes; rc.2 also
uses schema 2. Historical rc.1 restores schema 1 and requires matching callers
and fresh requests/results. Existing tags are never moved to roll back an install.

Hosted synthetic checks and discovery do not certify live Outlook behavior.
The warm ten-subject browse plus one selected 2000-scalar body <=10-second
target remains an unmeasured #9 acceptance criterion. Blocked COM calls/security
prompts can exceed cooperative budgets; partial results do not prove global
absence or newest matches. Outlook may synchronize and selected mail may reach
OpenCode's configured model; local COM is not guaranteed offline analysis.
Independent [#48](https://github.com/philfanzhou/MailLens/issues/48) tracks an
intermittent owned discovery-cleanup directory lock; it is outside this release
source change. Required candidate checks must actually pass, with any failure
and bounded retry recorded rather than hidden.

No mailbox writes, attachment content access, profile/store/policy changes or
Outlook termination are authorized. Keep mail, addresses, identifiers,
credentials, raw query results and live transcripts private, outside Git/public logs.
Any released-source fix needs a reviewed change and a newly authorized version;
never move or replace historical tags. Stable promotion changes VERSION/SHA and
requires its own reviewed PR, exact-candidate assessment, #9 signoff and explicit
publication direction; RC evidence does not carry over silently.
