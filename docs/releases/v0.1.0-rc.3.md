## Purpose and changes

This RC packages the OpenCode **2.0.28** adaptation and correction since rc.2,
and supplies a fixed candidate for native Windows/Classic Outlook validation
in [#9](https://github.com/philfanzhou/MailLens/issues/9). Live validation and
human model assessment remain **pending**. Stable `v0.1.0` still requires #9
and separate stable version/SHA/publication direction under
[#11](https://github.com/philfanzhou/MailLens/issues/11).

- [PR #38](https://github.com/philfanzhou/MailLens/pull/38): native discovery
  verification uses OpenCode 2.0.28's authenticated V2 API, bounded plugin
  activation readiness, strict envelope/skill identity/path/content checks,
  supporting resource bytes and explicit `resume:false` skill admission
  without a model request. The harness verifies the pinned Windows archive's
  SHA-512 integrity and actual binary version, isolates every subprocess,
  and cleans only owned services/sessions/files. All six real-installer
  lifecycle cases are retained, with parser/service/archive failure coverage.
- [PR #39](https://github.com/philfanzhou/MailLens/pull/39): README verification
  uses literal paths for resource enumeration and hashing, so directory names
  containing brackets cannot bypass the checks. Actual snippet probes compare
  all five package files and reject a corrupted supporting resource.
- Current installation/development instructions use the V2 discovery surface;
  historical OpenCode 1.18.30 results remain historical. Root VERSION and
  release/installation status are synchronized under #40.

Distribution: complete Git source snapshot and GitHub automatic source archives.
No standalone binary, extra release asset, package registry or marketplace.

Hosted synthetic checks and discovery do not certify live Outlook behavior.
The warm ten-subject browse plus one selected 2000-scalar body <=10-second
target remains an unmeasured #9 acceptance criterion. Blocked COM calls/security
prompts can exceed cooperative budgets; partial results do not prove global
absence or newest matches. Outlook may synchronize and selected mail may reach
OpenCode's configured model; local COM is not guaranteed offline analysis.

No mailbox writes, attachment content access, profile/store/policy changes or
Outlook termination are authorized. Keep mail, addresses, identifiers,
credentials, raw query results and live transcripts private, outside Git/public logs.
Any released-source fix needs a reviewed change and a newly authorized version;
never move or replace historical tags. Stable promotion changes VERSION/SHA and
requires its own reviewed PR, exact-candidate assessment, #9 signoff and explicit
publication direction; RC evidence does not carry over silently.
